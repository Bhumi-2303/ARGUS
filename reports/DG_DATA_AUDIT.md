## Specific Questions Addressed
### (a) NF-ToN-IoT Discrepancy
The `NF-ToN-IoT` dataset present is only ~9.1 MB and contains exactly 1,157,994 rows. 
This is **NOT** the full `NF-ToN-IoT-v2` dataset (which contains ~16.9M rows). Instead, it is the v1 dataset heavily truncated to just 12 columns (stripping away IPs and complex NetFlow fields). 
Comparing against `FINAL_DATASET_MANIFEST.json` and `reports/data_audits/DATASET_MANIFEST.json`, those manifests **correctly recorded** 1,157,994 rows and 12 columns. The discrepancy ('13.1M rows') mentioned in earlier experiments likely refers to a completely different dataset entirely (possibly full TON_IoT or a confusion with v2).

### (b) BoT-IoT Variant
- **Benign Flow Count:** 462
- **Benign Percentage:** 0.0042%
This variant is the **Original BoT-IoT (Argus extraction)** (specifically the 11-file 11M-row partial slice). 
Evidence: The columns present include `pkSeqID`, `stime`, `saddr`, `sport`, `daddr`, `dport`, and `state`. These are the exact features generated by the Argus flow tool used in the original paper. If this were `NF-BoT-IoT` or `v2`, the columns would be mapped to standard NetFlow v9 (e.g., `IPV4_SRC_ADDR`, `L4_SRC_PORT`, `IN_BYTES`).

### (c) TON_IoT Completeness
The TON_IoT network files are **INCOMPLETE** [REQUIRES VERIFICATION of full dataset availability]. The available `train_test_network.csv` has only 211,043 rows, which is merely the pre-sampled Train/Test subset. The full TON_IoT network dataset contains over 22 million rows across multiple CSVs that are currently missing from the `data/raw/` directory.
